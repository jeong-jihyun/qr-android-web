# 화면 검수 QA 에이전트 대응 절차 시나리오 (Playwright)

## 전체 흐름
개발 에이전트가 화면을 만든다 → QA 에이전트가 3가지 크기로 촬영·점검한다 → 문제표를 받는다 → 개발 에이전트가 고친다 → QA가 처음부터 다시 검사한다 (최대 3번) → 통과 또는 사람에게 넘김

## 준비 (처음 한 번만)
1. 터미널(명령 입력 창)을 열고 프로젝트 폴더로 이동한다.
2. `npm init -y` 입력 후 Enter (이미 package.json이 있으면 건너뜀)
3. `npm install -D playwright` 입력 후 Enter
4. `npx playwright install chromium` 입력 후 Enter (브라우저 내려받기, 몇 분 걸림)
5. `qa-screenshot.mjs` 파일을 프로젝트 맨 위 폴더에 둔다.
6. `qa/기준` 폴더를 만들고, 원래 이렇게 보여야 하는 이미지(또는 한 줄 설명 txt)를 넣는다.
7. package.json 맨 위 부분에 `"type": "module"` 줄이 없으면 추가한다. (.mjs 파일은 없어도 동작함)

## 시나리오 1. 클로드 코드
1. 프로젝트 폴더에 `.claude/agents` 폴더를 만든다.
2. `qa-screen-claude.md` 파일을 `.claude/agents/qa-screen.md` 이름으로 넣는다.
3. 클로드 코드를 실행하고 `/agents` 를 입력해 목록에 `qa-screen`이 보이는지 확인한다.
4. 개발 서버를 켜 둔다. (예: `npm run dev`)
5. 요청: "qa-screen 에이전트로 http://localhost:3000 의 / 와 /login 화면을 검수해 줘"
6. 에이전트가 촬영 → 점검 → 표로 보고한다.
7. 판정이 "수정 필요"이면: "위 표의 높음, 중간 문제를 고쳐 줘" → 고친 뒤 "qa-screen 다시 검수" (최대 3번)

## 시나리오 2. 오픈코드
1. 프로젝트 폴더에 `.opencode/agents` 폴더를 만든다.
2. `qa-screen-opencode.md` 파일을 `.opencode/agents/qa-screen.md` 이름으로 넣는다.
   (구버전은 `.opencode/agent` 폴더를 쓸 수 있으니 안 보이면 이 폴더로 옮겨 본다)
3. 오픈코드를 실행하고 입력창에 `@qa-screen` 을 쳐서 목록에 나오는지 확인한다.
4. 개발 서버를 켜 둔다.
5. 요청: "@qa-screen http://localhost:3000 의 / 와 /login 을 검수해 줘"
6. 모델이 이미지를 못 보는 종류면 자동 점검 결과(숫자, 글자)만으로 판정된다. 눈 확인이 필요하면 이미지를 볼 수 있는 모델로 바꾼다.
7. 수정 → 재검수는 시나리오 1의 7번과 같다.

## 시나리오 3. Playwright 직접 실행 (에이전트 없이)
1. 개발 서버를 켠다.
2. 터미널에서 `node qa-screenshot.mjs http://localhost:3000 / /login /dashboard` 실행
3. 결과 확인
   - `qa/screens/` : 화면별·크기별 스크린샷 (예: home_phone.png)
   - `qa/report.md` : 한눈에 보는 표
   - `qa/report.json` : 문제 상세 목록
4. "문제 있음"인 화면의 png를 열어 눈으로 확인한다.
5. 에이전트에게 넘길 때는 이미지를 붙여넣지 말고 파일 경로만 알려 준다.
   예: "qa/screens/home_phone.png 에서 버튼이 잘림, 고쳐 줘"

## 자동 점검 항목 (스크립트가 하는 일)
| 항목 | 설명 |
|---|---|
| 가로 넘침 | 내용이 화면 폭보다 넓어 가로 스크롤이 생김 |
| 화면 밖 요소 | 오른쪽으로 삐져나간 요소 이름과 픽셀 |
| 글자 잘림 | 글자가 상자보다 길어 잘림 |
| 이미지 깨짐 | 불러오지 못한 이미지 주소 |
| 콘솔 에러 | 브라우저 오류 메시지 |

## 한계 (미리 알아둘 점)
- 스크립트는 "넘침, 잘림, 깨짐"처럼 숫자로 잡히는 문제에 강하고, "예쁜지, 디자인과 같은지"는 눈 확인과 기준 이미지가 필요하다.
- 로그인이 필요한 화면은 로그인 처리를 스크립트에 따로 추가해야 한다.
- 애니메이션이 있는 화면은 촬영 시점에 따라 결과가 달라질 수 있다.
